# 本机发送实现与验收记录

## 当前状态（2026-11-07）

截至 2026-11-07：实现与离线测试通过；微信 4.2.0 在本机的界面读取验证受阻，完整免人工定位链路尚未通过。

当前已安装微信 4.2.0（270353）且登录已恢复；前台 AX 仍只返回窗口外壳，搜索框、输入框和发送控件不可读。

当前统一入口为 Python `scripts/wxsend`，已接 `wechat_automation.py` 的联系人解析、目标基线、自动导航、草稿准备、一次提交和发后核验。当前原生范围为 **person 文字单聊**；群、图片、公众号和系统联系人不因目录查询成功而获得发送支持。

## 已落地代码

- `contact_resolver.py`：新鲜 contact-only 副本；username、alias、备注、昵称精确匹配；跨字段碰撞不猜。`fresh_identity_catalog.py` 保持来源指纹、配置和短 TTL 检查。
- `native_backend.py` / `native_ax_bridge.swift`：账号与资料卡原始字段核对、搜索和聊天导航、控件语义与局部唯一性选择、实际进程/窗口/输入框/发送对象绑定。`resolveIdentity()` 已实现，不再是固定 `nil`。
- 默认原生后端、probe 与 inspect 不提交消息。实际消息控制器才显式开启草稿写入和真实提交；最终在绑定和精确草稿检查后，对指定发送对象调用 AXPress。保留 `LIVE_SEND_DISABLED` 作为缺少显式真实提交能力时的错误，不再把它描述为所有入口永久关闭。
- `send_guard.py`：准备、提交和精确清理状态机；前台与输入框焦点、在屏窗口、无模态、身份/对象/正文一致；已有草稿不覆盖；私有 journal 防重复提交。
- `receipt_session.py`：固定操作编号、私有状态、跨进程锁、提交前落盘、前后独立采样和严格目标核验。仅未提交失败阶段可在严格条件下恢复基线；已提交不重置；已核验成功持久保留，后续返回缓存。
- `cua_chat_controller.cjs`：备用 CUA 控制器；不把备用人工定位路径包装成原生完整自动化已验收。

## CLI 合同

| 命令 | 当前效果 |
|---|---|
| `wxsend --resolve <联系人>` | 只读新鲜联系人目录；公共输出为 hash |
| `wxsend --dry <联系人> --text <正文>` | 只读计划；不导航、不填框、不提交 |
| `wxsend --draft-check <联系人> --text <正文> --operation-id <ID>` | 真实导航、空框写入及精确清理，零发送 |
| `wxsend <联系人> --text/--text-file ... --operation-id <ID>` | 实际单聊文本链路，一次提交并核验 |
| `wxsend --inspect / --probe` | 诊断，默认无真实提交能力 |
| `wxsend --self-test` | 离线测试，无真实微信操作 |

操作编号统一为 `[A-Za-z0-9_-]{1,128}`，同一请求保持不变。默认优先使用 `~/WeChatDataAnalysis/.venv/bin/python`，最低 Python 3.10。`wxsend` 是需跟踪的 Python 源码，不再编译旧 `wxsend.swift` 覆盖它。

仅处理当前用户触发的前台任务，不启用后台定时或无人值守发送。新用户请求及当前明确授权的实机验证按其实际范围执行，不重复索要同一次任务授权；不重放已完成历史消息。

## 证据边界与待验收项

离线测试覆盖联系人歧义、身份与草稿不一致、精确清理、一次提交、异常结果不重发、基线恢复、缓存成功证据及严格新增记录核验。编译与离线通过只能证明相应组件和合成场景，不证明当前微信版本的导航可用。

**待实机结果补齐：实际版本/构建号、账号和目标聊天定位、草稿准备与精确清理、一次发送、新记录核验，以及测试范围。** 新版仍在验收时，不能写“无需人工定位已全面通过”。

`verified` 仅表示目标会话唯一匹配的新本人发出记录；`cached=true` 是历史成功证据；`delivery_confirmed` 不表示对方已收到或已读。失败必须说明实际阶段和是否进入发送动作。

## 简短历史边界

- 2026-11-03 至 11-04 的旧修复阶段，`wxsend` 及 Python/Swift 真实 Send 确曾硬编码关闭，身份解析未接通。该结论只对应当时源码，已由本次实现取代，不能作为当前全局发送禁令。
- 微信 4.1.15（270115）曾出现主窗口只有 AX 外壳或 AXWindows 为空；另一次正常重启后有可读搜索框、输入框和 Send 样本。还有自动化白屏但用户界面正常的现象。没有据此形成通用根因或保证重启有效的结论。
- 曾完成一次用户协助定位聊天后的 CUA 文字发送及唯一新增记录核验。这是受限路径成功，不等于新版原生自动找人已验收。
- 过去一次只读身份测试的审批范围、当时的零发送计数和历史跟进记录，均不是当前任务的执行规则，也不证明任何后台任务仍运行。[旧只读测试方案](identity-readonly-check.md)仅供理解历史试验，不用于阻止后来明确授权的开发或实机测试。
- 不把旧快照的账号、焦点或窗口位置当作当前状态；不因诊断返回默认禁用而反复要求登录或重启；不自动重复历史 VoiceOver 或权限变更试验。

当前使用流程见[发送流程](ui-sending.md)与 [SKILL.md](../SKILL.md)。私有配置、密钥、账号标识、运行日志和真实聊天内容留在本机，不进入公开仓库。
