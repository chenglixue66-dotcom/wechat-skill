# 历史只读身份诊断

本文保留旧修复阶段的诊断模块原理，**不是普通发送的前置审批流程**。当前用户请求的发送与实机测试按其已授权范围执行，统一入口和当前规则见 [SKILL.md](../SKILL.md) 与[发送流程](ui-sending.md)。不要把历史一次测试的限制扩展成所有后续任务的禁令。

## 模块用途

- `scripts/account_ui_observer.swift`：只读观察账号页字段，校验官方签名和进程实例；区分原始字符串、AttributedString 及有效范围。公共诊断输出仅保留 hash、长度和固定状态，不输出账号原文。
- `scripts/readonly_identity_navigation.cjs`：旧的 Settings → My Account 正常界面导航模块；逐步读取新鲜控件状态，不自行写入聊天草稿或提交消息。它不是当前完整自动发送控制器。
- `scripts/native_backend.py` 的资料卡读取和原始字段解析：获取局部作用域内的微信 ID 字段，检查资料卡、进程及窗口关联。解析成功本身不代表当前输入框已绑定。
- `scripts/fresh_identity_catalog.py`：创建短时独立联系人副本，精确映射原始字段并检查账号配置、源 DB/WAL/journal、来源 token 和 TTL；结束后清理临时副本。目录命中不等于 GUI 身份证明。

## 证据解释

诊断应记录当前采样状态，不能沿用历史账号、焦点或窗口位置。读取失败保留 unknown，不将空 AX 树当作空草稿，也不将配置账号当作当前登录账号。发现歧义或漂移时返回具体失败，不猜测字段拆分或优先选择预期账号。

只读解析或合成测试通过不能替代当前原生导航、空草稿准备、一次提交和结果核验。普通发送的实际身份与输入框绑定现由 `NativeBackend.open_chat()`、原生 `resolveIdentity()` 和 Guard 完成；默认诊断路径仍不发送。

## 数据边界

字段、目录副本、草稿检查和运行诊断均只在本机处理；密钥、账号原文、真实聊天正文及运行状态不写入公开仓库。仅为诊断而运行本模块不应附带修改系统保护、注入、Hook 或切换第三方发送服务。
